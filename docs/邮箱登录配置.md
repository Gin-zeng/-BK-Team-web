# 邮箱验证码登录配置

当前代码已支持邮箱验证码。首个验证成功的邮箱账号自动成为管理员，之后验证的邮箱为普通用户；原 ChatGPT 管理员保持有效。首次分配使用数据库事务及唯一记录，不能因并发请求产生多个首任邮箱管理员。

## 你需要准备什么

1. 在 https://resend.com 注册邮件发送服务账号。
2. 准备自己能管理 DNS 的域名。已有域名可添加专用发信子域，例如 mail.example.com。网站仍可使用现有 chatgpt.site 地址，无需迁移网站。
3. 在 Resend 的 Domains 添加发信域名，按它显示的准确记录配置 DNS，等待 Verified。不要复制示例域名；当前托管的 quirkyfinch.chatgpt.site 不属于你可管理 DNS 的域名，不能拿来验证。
4. 在 API Keys 创建仅用于发送邮件的密钥，权限尽量限定到该发信域名。
5. 编辑本项目未跟踪的 `.env.email-login.local`（已在本机创建）：

```dotenv
RESEND_API_KEY=在这里填写真实密钥
EMAIL_FROM=机械篮球战术室 <login@你的已验证发信域名>
EMAIL_AUTH_SECRET=保留文件中已经生成的随机值
```

不要把此文件提交、上传或发到聊天中。填写后告诉开发助手“邮件配置已填好”，即可将这三个值作为 Sites 运行时秘密配置并重新部署。单纯修改本地文件不会自动启用线上发信。

6. 部署后进入网站“管理后台”，输入邮箱、点击发送验证码、输入邮件中的6位验证码。请你本人首先完成一次验证以取得首个邮箱管理员权限。既有管理员不受影响。

参考官方文档：
- 已验证域名：https://resend.com/docs/dashboard/domains/introduction
- 发送接口：https://resend.com/docs/api-reference/emails/send-email

没有可管理的域名时，暂时继续使用原 ChatGPT 管理员入口。测试发件域名不能替代正式向球队成员发信的配置。邮件服务的开通、域名验证和真实收件验收仍需完成。

## 已实现的行为

- 验证码10分钟有效，每次只能使用一次；每个挑战最多尝试5次。
- 同邮箱60秒最多发送一次、每小时最多5次；同IP每小时20次、全站每小时100次。
- 登录会话7天有效，服务端保存令牌摘要；Cookie 为 HttpOnly、SameSite=Lax，线上加 Secure。
- 退出时删除服务端邮箱会话，同时退出原登录，避免仍留有其他管理员会话。
- 未配置邮件服务明确显示尚未配置；发送失败显示失败，不显示虚假发送成功。
- 不按用户自行输入的邮箱匹配旧管理员权限；必须实际收到并验证邮箱验证码。
- 普通用户不需要注册或登录即可浏览已发布内容。

## 验证及限制

运行 `node --test tests/domain.test.mjs tests/email-auth.test.mjs`。
本地集成验证脚本为 `tests/email-auth-browser.mjs`，只连接127.0.0.1，要求本地邮箱用户表为空。它向本地数据库写入测试挑战，模拟发送成功，仅测试验证码验证、并发首任管理员、权限与界面，不证明真实投递成功。不要改成在线地址运行。

数据库新增迁移 `drizzle/0001_outgoing_micromacro.sql`，不删除或覆盖现有管理员及比赛数据。首次邮箱管理员记录保存在 auth_bootstrap；撤销/重置首任分配目前不提供界面。
