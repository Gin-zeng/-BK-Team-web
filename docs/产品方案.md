# 机械学院篮球战术室

## 最终需求
第一阶段提供匿名浏览已发布内容、管理员维护数据、Excel/CSV导入校验、球员和比赛统计、10套以上二维战术教学、对手人工观察、持久化录像上传与播放。不公开样例数据，不根据缺失数据伪造结论。投篮/三分/罚球按出手/命中解释，投篮包含三分、不含罚球。

## 页面结构
球队总览；战术库及教学；比赛列表及分析；球员列表及详情；对手档案；录像中心；球队相册；管理员后台（内容、导入、发布、设置）。公开页面只读取已发布内容，身份认证与管理员权限分别处理。

## 数据模型
records以稳定ID保存球队设置、球员、比赛、战术覆盖、对手、录像、图片、相册；kind区分类型，status管理草稿/已发布，data保存经服务器校验的业务字段。比赛内部保存playerId关联的逐人统计、官方总计、原始行、复盘、日期和赛季。imports记录文件指纹、原始映射、差异处理、比赛ID及撤销状态。admins保存平台认证用户ID。uploads保存分片上传状态及所有者，完成后生成录像记录。文件保存R2；本地开发使用持久化Miniflare存储。

## 实施顺序
1. 认证、管理员初始化、D1/R2、发布过滤。
2. 导入预览、映射、校验、稳定ID、重复检测和撤销。
3. 数据页面与二维战术动画。
4. 对手资料、录像上传与播放、后台维护。
5. 单元/API验证、构建、响应式检查和交付。

## 后续阶段
第二阶段：视频时间片段标注、战术与录像联动、自由绘制编辑器、基于证据的定制分析助手。
第三阶段：经真实样本验证的追踪、自动事件识别、可选三维教学。

## 数据语义
全部0不代表未上场；默认出场状态未知。命中率按汇总分子分母计算；缺失值传播为不可用。样例助攻9与总计10、罚球出手11与总计10必须提示；由管理员记下处理理由。季节/日期不能由文件名26推断。
