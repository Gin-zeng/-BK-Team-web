## 一、项目事实（先读代码核实，不要凭猜测）

- 路径：`E:\篮球战术动画讲解平台\mech-hoops`（Git 仓库根）
- 技术栈：Next.js 16 App Router + React 19，但**用 vinext（Vite）构建**，产物是 Cloudflare Worker
- 运行时：Cloudflare Workers（`nodejs_compat`）+ D1（binding `DB`）+ R2（binding `BUCKET`）
- 命令：
  - `npm run dev` → vinext dev（127.0.0.1:5173）
  - `npm run build` → 产出 `dist/server/wrangler.json`
  - `npm run typecheck` → `tsc --noEmit`
  - `npm test` → 当前只跑 `tests/domain.test.mjs`
- 数据模型：`records` 单宽表 `(id, kind, status, data JSON, created_at, updated_at)`，
  `kind ∈ player|game|tactic|opponent|video|image|team`，`status ∈ draft|published`；
  另有 `imports / admins / uploads / email_users / email_sessions / email_codes / auth_bootstrap / auth_limits`
- 关键文件：
  - `app/page.tsx`（25KB / **49 行**，单页 SPA，hash 路由，全部展示组件内联）
  - `app/admin.tsx`（18.8KB / **58 行**，导出 `Editor / Importer / UploadMedia / Admin`）
  - `app/court.tsx`（SVG 战术动画播放器）
  - `app/api/{store,auth,media}/route.ts`（3 个接口端点，全 `force-dynamic`）
  - `lib/{stats,tactics,read-sheet,email-auth}.ts`（领域层，前后端共用纯函数）
  - `worker/index.ts`（Worker 入口，注入 Connector capability 后交给 vinext）

## 三、已知环境坑（先看，能省你半小时）

- `app/page.tsx`、`app/admin.tsx`、`app/globals.css` 是**被压缩成单行的巨型文件**。
  改逻辑前，先单独一个 commit 用 prettier 格式化（`npx prettier --write <file>`），
  再做功能修改 —— 否则 diff 不可读、review 无法进行。格式化 commit 里**不许夹带任何逻辑改动**。
- 若 `git push` 报 `cannot create standard input pipe ... Permission denied`，
  这是执行沙箱的进程管道限制，**不是代码问题**，不要为此改代码。
- 浏览器测试需要 Playwright + Edge；`tests/application-browser.mjs` 只允许连 localhost，
  它会做真实写入（导入、上传、撤销），跑完会自己清理。

### 批次 2 · 安全硬化（半天）

**2.1 公开接口输出白名单**（`app/api/store/route.ts` GET 分支）
- 现状：只对 `kind === 'game'` 剥离了 `official/rawRows/mapping/importId/resolution`，
  但 `video`/`image` 的 `data.key`（形如 `media/<uuid>`）**原样返回给匿名用户**
- 改法：抽一个 `publicShape(kind, data)`，按 kind 显式白名单输出；
  `video`/`image` 不返回 `key`，改为返回 `mediaUrl: '/api/media?id=' + id`
- 前置检查：先 `git grep -n "\.key" app/` 确认前端没有依赖该字段
- 验收：匿名 `curl /api/store` 返回体里搜不到 `"key"`；页面录像仍能播放

**2.2 统一安全响应头**（`worker/index.ts`）
- 拦截 `handler.fetch` 的 Response，注入：
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `X-Frame-Options: SAMEORIGIN`
  - `Strict-Transport-Security: max-age=31536000`（仅 https 时）
  - `Content-Security-Policy`：**先上 Report-Only**，因为站点大量使用内联 `style` 与 lucide 图标；
    确认无违规后再收紧。不要一上来就开强制模式。
- 验收：`curl -I` 能看到上述头；页面功能无回归

**2.3 同源校验硬化**（`app/api/store/route.ts` 的 `sameOrigin`，以及 `app/api/media/route.ts`）
- 现状：`if (origin && origin !== new URL(req.url).origin) throw` —— **缺 Origin 头时直接放行**
- 改为：有 Origin 必须严格相等；无 Origin 时必须 `Sec-Fetch-Site === 'same-origin'`，否则 403
- 注意：改完必须跑 `node tests/application-browser.mjs http://127.0.0.1:5173` 回归，
  确认浏览器同源写入不被误杀

**2.4 请求体积校验**（`app/api/store/route.ts` POST）
- 现状：只信 `content-length`，chunked 请求下该头缺失 → `Number(null||0)=0` → 完全绕过
- 改为：读取 body 后按实际字节数校验（上限 4MB），超限返回 413

**2.5 常量集中**
- 把散落的 4MB / 10MB / 8MB 分片 / 5GB / 1000 行等上限收进 `lib/limits.ts`

### 批次 3 · 前端性能与结构（1~2 天）

**3.1 修自定义战术动画抖动**（P0）
- 病因：`app/page.tsx` 里 `const custom = records.filter(...).map(r => ({...tactics.find(...), id: r.id, ...}))`
  每次渲染都产生新对象；`app/court.tsx` 的动画 effect 依赖整个对象
  `useEffect(..., [playing, step, speed, tactic])`，导致每帧取消并重建 rAF
- 修法（二选一，优先第一个）：`useMemo` 包住 `custom` 与 `library`；
  或把 `Court` 的依赖从 `tactic` 改为 `tactic.id`
- 验收：管理员从模板复制一条自定义战术，播放 10 秒不抖；React DevTools 中 effect 不再每帧重建

**3.2 路由切换不重复全量取数**
- 现状：`route()` 在每次 `hashchange` 都调 `void refresh()`，`refresh()` 并发打
  `/api/store` + `?action=session`，管理员再多打一次 `?admin=1`
- 改为：首次挂载取一次；只有写操作（保存/发布/删除/导入/撤销/上传）后刷新
- 验收：点遍 6 个导航，Network 面板只出现首屏那组请求

**3.3 拆分 `app/page.tsx`**
- 目标结构：
  - `app/views/{home,tactics,games,players,opponents,videos}.tsx`
  - `components/{Empty,MiniCourt,StatTable,Metrics,TeamTotals,Trend,GameDetail,VideoList}.tsx`
  - `app/page.tsx` 只保留路由壳（解析 hash、持有数据、分发 view）
- **纯结构重构，零行为变更**：逐组件搬移，搬一个测一个

**3.4 拆分 `app/admin.tsx`**
- 目标：`app/admin/{index,editor,importer,upload-media,history}.tsx`

**3.5 拆分 `app/globals.css`**
- 按区块拆成 `styles/base|layout|court|admin|charts.css`，或至少加分区注释

**3.6（可选）类型收口**
- 把 45 处 `: any` / `as any` 逐步替换成 `lib/types.ts` 里的
  `RecordOfKind`、`GameRecord`、`PlayerRecord` 等判别联合类型
